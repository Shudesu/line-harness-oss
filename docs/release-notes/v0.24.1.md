# L Harness v0.24.1

v0.24.0以降の更新・セットアップ、配信先の分離、認証、操作画面の修正をまとめた安定版です。
CLIは `create-line-harness@0.2.12`、更新エンジンは `@line-harness/update-engine@0.0.13` を使用します。

## 主な変更

- 旧環境からの更新で、マイルの付与済み履歴と未処理履歴を区別して引き継ぎます。
  既存の付与記録を変更せず、判定できない履歴は停止して確認を求めます。
- セットアップの保存済みリリースを明示的に変更できるようになりました。
  認証設定の失敗で再開情報を失わず、Git操作中に編集されたWorker設定も保護します。
- タグ・セグメント配信のアカウント分離、タグ自動化後のシナリオ開始、
  リッチメニュー切替、チャット返信のURL計測と送信ログを修正しました。
- 顧客情報APIの認証とリンク処理、管理画面のCORS、LIFF経由のOAuth引き継ぎを修正しました。
  テキストのキーワードは全角・半角と前後空白を揃えて判定します。postback値はそのまま扱います。
- 更新ダイアログの見切れ、タイムゾーンをまたぐ予約の重なり、問い合わせ日時のJST表記を修正しました。
- 未対応一覧・サイドバーの定期取得を非表示時・5分間無操作時に停止し、
  友だち一覧のタグをページ単位で一括取得します。
- プラグインマーケットのベータ版と独立したプラグイン雛形を追加しました。

## インストール済み環境の更新

Node.js 20以降で、保存済み設定のあるディレクトリを指定して実行してください。
標準の `~/.line-harness` を使っている場合は `--repo-dir` を省略できます。

```sh
npx create-line-harness@0.2.12 update --repo-dir "/path/to/existing/install"
```

この安定版の更新manifestはschema 2です。旧管理画面や旧CLIの更新処理は
この形式を拒否するため、更新確認でエラーになった場合も上記のCLIを使ってください。
新CLIはschema 1と2の両方を読み取れます。

## v0.24.0でセットアップが途中停止した場合

保存済みリリースが旧版のままでは、通常の再実行でも同じ版が選択されます。
v0.24.1の公開後、同じインストール先で次を実行すると、DB・資格情報を保ったまま
検証済みのリリースへ再開先を変更できます。

```sh
npx create-line-harness@0.2.12 setup --release 0.24.1 --repo-dir "/path/to/existing/install"
```

`--release` はセットアップ専用です。`--from-source` とは併用できません。
ソース版のセットアップは同じチェックアウトで `--from-source` を付けて再開してください。
DB、マイグレーション台帳、`.line-harness-setup.json` を削除して回避しないでください。

履歴の所有者や独自のマイル付与ルールを確認できない場合、更新は安全のため停止します。
元のマイルSQLを手動で再実行せず、[履歴更新の条件と復旧方法](../UPDATE-MILEAGE-REPLAY.md)を確認してください。
この更新は、既に重複している残高の取消・修復は行いません。
