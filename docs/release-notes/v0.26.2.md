# L Harness v0.26.2

## ウェビナー管理の権限統一

ウェビナーの削除、管理用コメントの一括更新、CTAカードの一括更新をowner/adminに限定しました。staffおよび権限コンテキスト未設定の要求は403で拒否し、DBの参照・更新に進みません。owner/adminの正常操作と入力検証は維持します。

視聴者用のLIFF API（視聴進捗、コメント投稿、予約、CTAクリック、フォーム行動計測、相談予約）は従来の本人確認を維持します。

## v0.26.1以降にmainへ取り込まれた変更

この版は最新mainから作成しています。ウェビナーの権限修正に加え、以下の既存変更も含みます。

- スタッフAPIキーと管理セッションのハッシュ保存、更新APIのCookie/CSRF認証、受信画像の認証、APIスコープ、任意のCloudflare Access検証。
- Instagram連携リンクの署名付きトークン検証。
- アカウントを指定したLINE user ID検索と、送信・タグ・コンバージョンAPIの任意のIdempotency-Key対応。
- 接続ヘルス診断とWebhook endpointの確認・明示的な修正操作。
- 管理画面の認証待ち表示、チャットの再取得・スクロール・未読表示の改善。

## 更新時の注意

ウェビナーの権限修正自体はDB変更を追加しません。ただし、v0.26.1からの更新では既存mainに追加された次のmigrationが対象です。

- `074_security_hardening.sql`
- `075_ig_link_token_uses.sql`
- `076_api_idempotency_keys.sql`
- `077_api_line_sends.sql`

[認証強化の移行手順](../SECURITY-UPGRADE.md)を先に確認してください。Worker更新前のmigration、スタッフキーのバックフィル、全ユーザーの再ログイン、旧ADMIN_API_KEY依存の解消が必要です。既存DBへschema.sql/bootstrap.sqlを代用しないでください。

Instagram連携の署名トークンは既定ではoffです。[IG連携の移行条件](../IG_LINK_TOKEN.md)に従って相手側の対応後に有効化してください。Idempotency-Keyの対応範囲と再試行条件は[API仕様](../api-idempotency.md)を参照してください。

このリリース作業では、本番デプロイ・D1 migration・実送信は実施しません。配布物はタグCIで検証・ビルドし、GitHub Releaseへ添付する方式です。npm CLI公開は別の手動ワークフローで、このWorker修正ではCLIパッケージの版を変更しません。
