# L Harness v0.24.3

Meet コールバックと Stripe Webhook の送信元検証を必須にしたセキュリティ更新です。

## 修正内容

- Meet の通知は `MEET_CALLBACK_SECRET` と `X-Meet-Signature` による HMAC-SHA256 署名を検証してから処理します。
- Meet の結果通知を Harness プロキシ経由に変更し、送信履歴の記録に対応しました。所属アカウントの設定が見つからない場合、別アカウントから送信しません。
- Stripe の `STRIPE_WEBHOOK_SECRET` 未設定時に署名検証を省略する処理を廃止しました。
- 両エンドポイントで、署名キー未設定・空白のみは503、署名不正・欠落・前後5分を超えた時刻は401で拒否します。拒否時はDB更新やLINE送信を行いません。
- Stripe の複数署名によるキー更新をサポートし、既存のイベントIDによる重複処理抑止を維持しました。
- 管理画面のバージョン表示とAPIのバージョンを0.24.3に更新しました。

## 更新前の確認

この変更は本番・開発ともに適用されます。Stripe または Meet を利用中の場合、先に受信側の署名キーと送信側の署名対応を準備してください。キー未設定で更新すると、その連携は受信停止になります。連携を使わない環境では未設定のままで構いません。

Meet の送信側は、`timestamp + "." + rawBody` を共有シークレットで HMAC-SHA256 署名し、`X-Meet-Signature: t=<秒単位Unix時刻>,v1=<小文字16進署名>` を付けます。再送時は時刻と署名を作り直してください。5分以内の同じ通知の再送では、Meetの再通知が発生する場合があります。

設定の詳細は [デプロイ手順](../wiki/21-Deployment.md#シークレット設定) を参照してください。Workerと管理画面をセットで更新します。今回追加のDBマイグレーションはありません。

## 検証

署名キー欠落、不正署名、本文改ざん、期限切れ、未来時刻、不正JSONの拒否と副作用の不発生をテストしました。正規の購入処理、Stripeの重複イベント、Meetのアカウント別プロキシ送信も検証しています。テストによる顧客への実送信は行いません。
