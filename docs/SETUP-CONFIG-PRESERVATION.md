# セットアップ時のWorker設定の保護

`setup` は公開リリースに対応するGitタグへ移動します。通常のインストール先だけでなく、`--repo-dir` や現在のディレクトリも対象になるため、`apps/worker/wrangler.toml` の手編集を自動で破棄しません。

Git上に変更がある場合、次の条件をすべて満たした設定だけをCLIの生成物として扱います。

- Gitの追跡対象で、ステージしていない内容変更だけである。
- `.line-harness-config.json` を読み取り、生成に必要な設定を解決できる。
- その設定から現在のCLIが生成する内容と、ファイル全体が完全に一致する。

「Generated by create-line-harness」という行が残っていても、それだけでは上書きしません。生成後に追加した独自のDO、KV、サービスbindingなども手編集として保護します。

確認できない変更があれば、公開リリースのタグ取得・切り替えより前に停止します。通常インストール先の自動pullも行わず、現在のチェックアウトをそのまま返します。自動でstash、commit、変更破棄は行いません。`--repo-dir` と現在のディレクトリを単に使うだけの経路は維持するため、復元待ちのsnapshotがない通常の `--from-source` を新しく禁止することはありません。

再開時に古いsnapshotから設定を復元する場合は、source・公開リリースの両方で事前確認します。現ファイルがsnapshotそのもの、または保存済みaccount/database IDをCLIの既知の方法で置換した内容と完全に一致する場合だけ復元します。中断後の手編集などで一致しなければ、現ファイルと状態ファイルを残して停止します。

正確に確認できた生成物は、Git操作の間だけ元の追跡ファイルへ戻します。その直前に、内容・権限・index・HEADが最初の確認時と同じか再確認します。タグ取得の待ち時間に変更された場合は、変更を保持して停止します。

Git操作の後も、現ファイルとindexがGitの結果に一致し、一時ファイルの権限が変わっておらず、HEADが元の版か取得した版であると確認できる場合だけ、生成物の内容と権限を復元します。途中に編集・権限変更・stage・別commitが入って復元の安全性を確認できない場合は、現ファイルとindexを上書きしません。元の生成設定を本人だけがアクセスできる一時ディレクトリへ退避し、保存先を示して停止します。退避ファイルは0600、ディレクトリは0700で作成します。

タグ取得に失敗した場合は、設定ファイルを変更しません。Gitの切り替えが成功した後に依存インストールだけ失敗した場合は、取得したタグを維持し、設定ファイルを残した状態でエラーを返します。

## 保護のために停止した場合

手編集を含むファイルをバックアップし、独自の設定を使い続ける場合は[手動更新ガイド](wiki/26-Manual-Update.md)に従ってください。標準構成で新しく導入する場合は、別のクリーンなインストール先を用意します。エラーを消すためだけに設定やセットアップ状態を削除しないでください。

操作中の変更を検出して退避先が表示された場合は、現在の設定と退避された生成設定を比較します。新しい手編集を消さないよう、退避ファイルをそのまま現在の設定へ上書きせず、必要な項目を確認してください。元のmodeとGit情報は同じディレクトリの `snapshot.json` に保存されます。

古いCLIの生成物でも、現在の生成形式と一致しなければGitの自動変更を止めます。この保護の対象はpin・pull・snapshot復元です。独自のbindingを公開リリースへ自動移植する機能ではなく、source deploy全体での独自bindingの保持を保証するものでもありません。独自構成の本番環境へ標準セットアップを再適用する用途では、手動の設定確認が必要です。
