# 28. Googleカレンダー連携とライブCTA即時予約

LINE Harnessでは、オートウェビナーのフォーム送信後に空き日程をその場で表示し、個別相談の予約、Google Meetの発行、LINE通知までをまとめて完了できます。

このページでは、普段使う人の設定と、OSSを設置する人が最初に一度だけ行う設定を分けて説明します。

---

## できること

ユーザーはライブ画面を閉じずに、次の流れで個別相談を予約できます。

```text
ウェビナー視聴
  → CTAをタップ
  → フォームを送信
  → 空いている日時を選択
  → 予約確定
  → Google Meetを自動発行
  → LINEで確定通知
  → 前日・1時間前にLINEリマインド
```

スタッフ側では、LINE Harnessに「普段受け付ける曜日と時間」を登録します。Googleカレンダーにすでに入っている予定は、その時間帯から自動で除外されます。

### 空き枠の考え方

たとえば、LINE Harnessで月曜日の受付時間を `10:00〜19:00` に設定し、Googleカレンダーに `13:00〜14:00` の予定がある場合、13時台は予約候補に出ません。

空き枠は次の順番で決まります。

1. LINE Harnessの「毎週の受付時間」を土台にする
2. その日に「日付別の応急枠」があれば、毎週設定より優先する
3. LINE Harness内の既存予約を除く
4. Googleカレンダーの「予定あり」の時間を除く
5. 現在から60分以内の枠を除く
6. 予約メニューの所要時間と、予約後の余白時間を反映する

ライブCTAには、今日から14日先までの候補が30分刻みで表示されます。相談自体の長さは、予約メニューに設定した所要時間です。

> Googleカレンダーは、LINE Harnessで設定した受付時間を勝手に広げません。受付時間の中から、予定が重なる部分だけを閉じます。そのため、自分の自由時間まで全部予約枠になることはありません。

---

## 普段使う人の設定

Google Cloudやシークレットの設定が済んでいる環境では、次の操作だけで使えます。

### 1. 予約メニューを用意する

管理画面の「予約管理 → メニュー」で、個別相談用のメニューを作成します。

- メニュー名: 例 `AI活用 個別相談`
- 所要時間: 例 `15分`
- 予約後の余白: 必要に応じて設定
- 有効: ON

次に「メニュー × スタッフ」で、担当スタッフがこのメニューを提供する設定にします。

### 2. 毎週の受付時間を保存する

管理画面の「予約管理 → スタッフ」から担当者の「受付時間」を開きます。

曜日ごとに、実際に相談を受けられる範囲だけを設定して「受付時間を保存」を押します。

例:

| 曜日 | 受付時間 |
|------|----------|
| 月〜金 | 10:00〜19:00 |
| 土 | 10:00〜19:00 |
| 日 | 受付しない |

この設定には終了日がありません。一度保存すれば、将来の日付にも毎週自動で適用されます。

### 3. Googleアカウントを接続する

同じ画面の「Googleカレンダー連携」で「Googleアカウントで接続」を押します。

1. 予約管理に使うGoogleアカウントを選ぶ
2. Googleカレンダーへのアクセスを許可する
3. LINE Harnessへ戻る
4. 画面に「接続済み」と表示されることを確認する

OAuth方式では、サービスアカウントキーの発行や、カレンダーの共有設定は不要です。

### 4. ウェビナーと予約メニューを結び付ける

対象ウェビナーのフォローアップ設定に、先ほど作った予約メニューを指定します。ライブCTAで使用するフォームも、そのウェビナーのCTAカードに設定してください。

現行のOSS版では、この結び付けはAPIまたはD1で設定します。`webinar_followup_configs` の対象ウェビナー行に、次の値を保存します。

- `booking_menu_id`: 個別相談メニューのID
- `booking_url`: 空き枠を取得できない場合に表示する予備の予約URL
- `is_active`: `1`

すでにフォローアップ設定がある場合の例:

```sql
UPDATE webinar_followup_configs
SET booking_menu_id = 'YOUR_BOOKING_MENU_ID',
    booking_url = 'https://example.com/booking',
    is_active = 1
WHERE webinar_id = 'YOUR_WEBINAR_ID';
```

> IDやURLは自分の環境の値に置き換えてください。Google OAuthのクライアントシークレットやアクセストークンをSQLへ保存しないでください。

### 5. テスト予約する

本番配信の前に、テスト用のLINEユーザーで次を確認します。

- ライブのCTAからフォームを送信できる
- 送信後に空き日時が表示される
- Googleカレンダーの予定がある時間は表示されない
- 日時を選ぶと予約が確定する
- Googleカレンダーに予定とGoogle Meetが作られる
- LINEに日時とMeet URLが届く
- 同じ枠をもう一度予約できない

---

## 予約後に自動で行われること

日時を選ぶと、サーバーが空き状況をもう一度確認してから確定します。画面を開いた後に別の人が先に予約していた場合は、二重予約にせず別の日時を選び直してもらいます。

予約が確定すると、次が一括で行われます。

- LINE Harnessの予約を「確定」で保存
- Googleカレンダーに予定を作成
- Google Meet URLを発行
- Meet相談として登録
- 前日と開始1時間前のLINEリマインドを予約
- 申込者へ日時とMeet URLをLINE通知

GoogleカレンダーやMeetの作成に失敗した場合は、中途半端な予約を残さず取り消します。Googleカレンダーを確認できない場合も、安全のため空き枠を表示しません。

なお、ライブCTAから直接予約できるのは、そのウェビナーでCTAフォームを送信した本人だけです。

## OSS設置者が最初に一度だけ行う設定

ここからは、LINE HarnessをCloudflareへ設置・管理する人向けです。普段の運用担当者は、この章の操作を行う必要はありません。

### 1. Google Calendar APIを有効にする

Google Cloud Consoleでプロジェクトを選び、「APIとサービス」からGoogle Calendar APIを有効にします。

### 2. OAuth同意画面を設定する

Google Auth Platformでアプリ情報を登録します。

- アプリ名: 例 `LINE Harness`
- サポートメール: 管理できるメールアドレス
- 対象: 組織内だけなら「内部」、組織外アカウントも接続するなら「外部」

「外部」を選んでアプリをテスト状態で使う場合は、接続するGoogleアカウントをテストユーザーへ追加してください。本番運用ではGoogleの案内に沿って公開状態も確認します。テスト状態のままでは、付与された認可や更新トークンが短期間で失効する場合があります。

データアクセスには、次の2つだけを追加します。

```text
https://www.googleapis.com/auth/calendar.events
https://www.googleapis.com/auth/calendar.events.freebusy
```

前者は予定とGoogle Meetの作成、後者は予定が埋まっている時間の確認に使います。

### 3. OAuthクライアントを作成する

OAuthクライアントIDを「ウェブ アプリケーション」として作成します。

承認済みのリダイレクトURIには、公開Worker URLに次のパスを付けて登録します。

```text
https://YOUR_WORKER_DOMAIN/api/booking/google-calendar/oauth/callback
```

例:

```text
https://your-worker.workers.dev/api/booking/google-calendar/oauth/callback
```

末尾のスラッシュを追加せず、実際に管理画面が接続しているWorkerのドメインと完全に一致させてください。

### 4. Workerシークレットを設定する

作成したOAuthクライアントのIDとシークレットをCloudflare Workerへ登録します。

```bash
cd apps/worker
npx wrangler secret put GOOGLE_OAUTH_CLIENT_ID
npx wrangler secret put GOOGLE_OAUTH_CLIENT_SECRET
```

設定後、Workerを再デプロイします。

```bash
pnpm deploy
```

クライアントシークレットJSONや、その中身をGitへ追加しないでください。シークレットはWorker secretとして保存します。

### 5. 管理画面で接続を確認する

「予約管理 → スタッフ → 受付時間」を開き、「Googleアカウントで接続」が表示されれば、設置者側の準備は完了です。

---

## サービスアカウントキーが作れない場合

次の組織ポリシーで、サービスアカウントキーの作成が止められていることがあります。

```text
iam.disableServiceAccountKeyCreation
```

このポリシーを無理に解除する必要はありません。LINE Harnessでは、より安全なOAuth方式を推奨します。管理画面の「Googleアカウントで接続」を使えば、サービスアカウントキーもカレンダー共有も不要です。

既存環境との互換性のためサービスアカウント方式も残っていますが、新しく設定する場合はOAuth方式を選んでください。

## よくあるエラー

| 表示・症状 | 主な原因 | 解決方法 |
|------------|----------|----------|
| `redirect_uri_mismatch` | Google Cloudに登録したURIとWorkerのコールバックURIが一致していない | Workerの公開URL + `/api/booking/google-calendar/oauth/callback` を完全一致で登録する |
| `This request contains scopes that cannot be requested together` | 同じGoogle OAuth認可で、DriveやYouTubeなど過去の権限が混ざっている | 最新のLINE Harnessへ更新し、再接続する。LINE HarnessはCalendarの2権限だけを要求する |
| `ACCESS_TOKEN_SCOPE_INSUFFICIENT` / FreeBusy 403 | 空き時間確認の権限が不足している | `calendar.events.freebusy` を同意画面へ追加し、最新のLINE Harnessから再接続する |
| 許可後も「未接続」のまま | コールバックURI、Workerシークレット、OAuth公開状態のいずれかが不正 | URLを再読み込みし、直らなければWorkerログの `Google Calendar OAuth callback failed` を確認する |
| 数日後に急に空き枠が出なくなった | 外部向けOAuthアプリがテスト状態のまま、またはGoogle側で許可を取り消した | OAuthアプリの公開状態とテストユーザーを確認し、管理画面から再接続する |
| 空き枠が1件も出ない | 受付時間外、60分以内、既存予約、Googleの予定あり、メニュー未設定のいずれか | 毎週の受付時間、日付別枠、予約メニュー、Googleカレンダーを順に確認する |
| Googleの予定がある時間も出る | 予定が「空き時間」扱い、または別アカウントのカレンダーを接続している | Google側で予定を「予定あり」にし、正しいアカウントを再接続する |
| 日程確定後にMeetがない | 古いバージョン、Google連携切れ、Meet作成権限不足 | 最新版へ更新してGoogleを再接続する。現在のライブCTA予約はMeetを作れない場合、予約自体を確定しない |

---

## 安全に運用するための確認表

- 受付時間は、本当に相談を受けられる曜日と時間だけにする
- 私用予定をGoogleカレンダーへ「予定あり」で入れる
- 本番配信前に、フォーム送信からMeet発行までを1回通す
- OAuthクライアントシークレットをGit、D1、チャットへ貼らない
- Google連携を変更した後は、空き枠から既存予定が除外されることを確認する
- 予約キャンセル時は、LINE Harness上の予約とGoogleカレンダーの両方を確認する

これで、視聴中の熱量を落とさずに、その場で個別相談の日程まで確定できます。
