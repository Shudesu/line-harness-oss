# 配信の送信元と失敗結果

配信時は保存された送信元アカウントを確認します。指定先が存在しない、無効、トークン未設定、DBで確認できない場合は送信しません。即時・予約・キュー・セグメント投入で同じ検証を使います。

旧形式の `line_account_id = NULL` は、登録アカウントのない従来環境に限り環境設定の送信元を使います。アカウントが登録されている環境では、1件だけでも送信元を推測しません。未指定の既存配信は止め、送信元と既配信の有無を確認してください。配信の本文・宛先を自動で付け替える処理や、既存データの削除は行いません。

単一アカウントの即時送信では、バッチ失敗時に後続バッチを中止し、LINEが受け付けた人数と失敗理由を残します。受付後の履歴・集計保存失敗や受付結果不明の配信を、自動再送できる下書きへ戻しません。DBが書き込めない場合も呼び出し側が送信ロックを解除しないようにします。

既存DBのstatus列は維持します。`sent` は処理終了を表すため、**成功判定にはlast_errorとsuccess_countも確認**してください。異常が残る配信は画面に「要確認」と理由を表示し、即時送信APIも502を返します。LINEの受付人数は端末への到達を保証する人数ではありません。

キュー送信は従来の進捗と再試行キーを維持し、失敗理由を表示します。一般バッチの送信ログ保存失敗は、受付人数を失わず完了後にも表示します。個別化送信の受付後ログ保存失敗も、LINEによる拒否とは区別します。

## 残る改善範囲

これはIssue #64全体の完了ではありません。キューの受信者・リクエストの永続スナップショット、再試行期限、停止・再開操作、監査履歴の拡張は別途扱います。LINEの再試行キーの重複抑止は初回から24時間以内・同一内容のリクエストが前提です。期限を過ぎた配信や結果不明の配信を、一律に再送しないでください。
