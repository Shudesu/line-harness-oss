# 条件タグ付けプラグイン

友だちのメタデータを調べ、条件に合う人へ既存のタグを追加する公式プラグインです。初期ルールは「`visitCount` が数値で3以上」。タグ追加をトリガーにしたシナリオへつなげられます。

## 本体の外に作る

L Harnessリポジトリのルートで実行します（Node.js 22以上）。

```bash
pnpm plugin:create ../my-tag-plugin
cd ../my-tag-plugin
npm install
npm run typecheck
npm run build
git init
```

`src/rules.ts` の `matchesRule` を変更すると独自条件にできます。本体の `apps/` や `packages/` を編集する必要はありません。生成先に親設定・workspace依存はなく、別リポジトリとして管理できます。SDKは公開済みの `0.24.0` に固定しています。生成した `package-lock.json` も管理してください。

## 接続と確認

1. 本体の管理画面で対象タグを作成し、タグIDとLINEアカウントIDを確認します。
2. `wrangler.jsonc` の `LINE_HARNESS_API_URL`（本体APIのオリジン。管理画面の `/console` は付けない）、`LINE_ACCOUNT_ID`、`TARGET_TAG_ID` を設定します。
3. ローカルだけの `.dev.vars` を作り、`LINE_HARNESS_API_KEY=実際のAPIキー` を設定します。Gitには含めません。APIキーを利用するため、本体の管理者がセットアップしてください。
4. `DRY_RUN` は `"true"` のままで、ローカルの定期処理を呼びます。

```bash
npm run dev
# 別のターミナルで（本体ではなく、起動したプラグインのローカルURL）
curl 'http://localhost:8787/__scheduled?cron=0+*+*+*+*'
```

ログの `scanned`（確認数）、`matched`（タグ未付与の候補数）、`applied`（付与数）を確認します。確認モードでは読み取りだけを実行します。

## 有効化・停止

条件を確認したら `DRY_RUN` を `"false"` にして、まずテスト用アカウントで実行します。タグ追加は既存のシナリオやオートメーションを開始することがあるため、接続先の配信設定も確認してください。

定期実行は `triggers.crons` を `["0 * * * *"]` に変更すると毎時になります。公開先は本体と異なるWorker名を使います。

```bash
npx wrangler secret put LINE_HARNESS_API_KEY
npm run deploy
```

停止は `triggers.crons` を `[]` にして再デプロイします。停止しても付与済みタグや開始済みシナリオは取り消されません。必要に応じて本体側でシナリオを停止してください。

## 動作範囲

- 指定アカウントのフォロー中の友だちだけが対象。別アカウントが返った場合は書き込み前に停止します。
- 1回最大1,000件。これを超える場合は書き込み前に停止するため、差分同期やキュー方式への拡張が必要です。
- 既存の対象タグを持つ友だちは除外し、追加直前にも再確認します。通常の再実行では同じタグを追加しません。
- 同じタグを付ける複数のWorkerの並行実行に対して、厳密な排他はありません。1つの定期処理として運用してください。
- タグの削除、メッセージの直接送信はしません。ルールを満たさなくなってもタグは残ります。
- エラーは処理を中断します。途中まで成功したタグは残り、再実行時には除外されます。
- メタデータは事前に本体APIなどから登録してください。`"3"` のような文字列は数値条件に一致しません。
- APIキーに対してプラグイン専用の権限制限は付与されません。キーは信頼できるサーバー側にだけ保存してください。

## 本体アップデート時

独自ソースは本体外に残ります。API互換性は別に確認が必要です。本体の更新前にテスト用環境で `DRY_RUN="true"` の結果を確認し、利用するSDKを変えるときは型検査とビルドを実施します。本体のD1へ独自テーブルを作らず、必要な状態はプラグイン専用DBへ保存してください。
